# TASK-004 — Unify measurement, layout, theme, text, and authoring foundations

## Goal

Components use one deterministic measurement/layout system, semantic theme resolution, shared text contracts, and constrained part authoring.

## Context

Layout, Unicode width, capability-aware styling, semantic surfaces, and slots/parts are cross-cutting contracts. Establish them before component families so each family consumes the same foundation.

Dependencies: TASK-002, TASK-003. Canonical contracts: [architecture/overview.md](../../../docs/architecture/overview.md), [api/authoring.md](../../../docs/api/authoring.md), [foundations/layout.md](../../../docs/foundations/layout.md), [foundations/theme.md](../../../docs/foundations/theme.md), [foundations/text.md](../../../docs/foundations/text.md), [foundations/author.md](../../../docs/foundations/author.md).

## Preconditions

- **P-001:** The caller has supplied a committed descendant of annotated `visual-baseline` (`4a79c0a2d40fca46fc406b77157ce3b3f12ec16b`) on `termrock-implementation`.
- **P-002:** The linked canonical architecture, API, component, design, and verification documents are present.
- **P-003:** The future implementation environment provides `rtk` and `cargo nextest`.

## Scope

In scope:

- Measure/draw geometry, clipping, Unicode and continuation handling, semantic style resolution, text model, and constrained slots/parts.

Out of scope:

- Per-component layout engines, ad hoc colors, duplicate text editors, and output restyling.
