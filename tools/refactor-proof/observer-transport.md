# Observer transport

## Scope and status

This note documents the Observer transport as it appears in the reviewed source snapshot at PR38 revision 35303f52f218b74dea9b864e19e4b9f10d06d95e. It distinguishes that implementation from an authentic but unrelated historical launcher and from a synthetic test fixture. The historical producer is not a current launcher contract. This is source documentation, not a fresh execution, transport-safety, or production-readiness receipt.

The original design note described an observer owned by a planner outside the host sandbox. It assigned the request pipe's write end and response pipe's read end to the host, supplied an unpredictable nonce per fixture, and required worker subprocesses to receive none of those three environment values. It also described the build, test, taskfmt request sequence. This remains useful intended-contract context; it does not identify a producer in the reviewed PR38 tree. See the [original design note](https://github.com/tailrocks/terminal-components-claude/blob/c1425251705f667c1a307b637efee67fe4975d69/tools/refactor-proof/README.md#L68-L86).

## Reviewed PR38 interface

The [reviewed IPC types](https://github.com/tailrocks/terminal-components-claude/blob/35303f52f218b74dea9b864e19e4b9f10d06d95e/tools/refactor-proof/src/observer/ipc.rs#L1-L68) define these environment names:

| Name | Role represented by the current client |
| --- | --- |
| TC_PROOF_OBSERVER_REQUEST_FD | Request descriptor read from the environment |
| TC_PROOF_OBSERVER_RESPONSE_FD | Response descriptor read from the environment |
| TC_PROOF_OBSERVER_NONCE | Nonempty request nonce |

The current request schema is tc-proof-observer-request/v1. Each request contains a nonce and a step; the client’s fixed verify sequence is build, test, then taskfmt. The [current client](https://github.com/tailrocks/terminal-components-claude/blob/35303f52f218b74dea9b864e19e4b9f10d06d95e/tools/refactor-proof/src/observer/client.rs#L41-L155) encodes newline-terminated JSON and limits the encoded request including its newline to at most 4096 bytes. It writes and flushes one request, then reads response bytes using `read_until` for a newline. The response length is checked against 4096 bytes after reading; this is not a streaming allocation bound. The reader removes a trailing newline when present, but it does not reject nonempty EOF data solely for lacking that newline. Newline framing is the intended protocol, not a fully enforced response-termination guarantee in this implementation. A tc-proof-observation/v1 response carries step, tree, argv, exit, stdout, stderr, and files fields; a tc-proof-observer-error/v1 response is mapped to ObserverUnavailable. The type definitions expose strings and a map for these payloads; this note does not claim additional encoding, unknown-field rejection, or response-binding checks beyond the reviewed code.

In the reviewed [host verify path](https://github.com/tailrocks/terminal-components-claude/blob/35303f52f218b74dea9b864e19e4b9f10d06d95e/tools/refactor-proof/src/host/verify.rs#L62-L95), verify validates the frozen run and related inputs, constructs one ObserverClient from the environment, then asks it to execute the fixed sequence. The pinned tree exposes the client and these names, but the bounded source search found no production code in that tree that creates the pipe pair or sets the three environment values.

## Ownership remains under review

In the reviewed [client implementation](https://github.com/tailrocks/terminal-components-claude/blob/35303f52f218b74dea9b864e19e4b9f10d06d95e/tools/refactor-proof/src/observer/client.rs#L42-L70) and its [owned-FD conversion](https://github.com/tailrocks/terminal-components-claude/blob/35303f52f218b74dea9b864e19e4b9f10d06d95e/tools/refactor-proof/src/observer/client.rs#L163-L169), from_env parses the two environment values as signed descriptor numbers, reads a nonempty nonce, and wraps the descriptor numbers as owned files through an unsafe raw-descriptor conversion. The source does not establish unique ownership of arbitrary environment values and does not validate descriptor range or distinctness before taking ownership. Equal descriptor numbers or repeated construction can create multiple owners or reuse stale descriptor numbers. Even checking that a descriptor is open would not prove exclusive ownership. A valid uniquely owned non-pipe descriptor is a transport mismatch, rather than automatically a raw-FD ownership violation. The public require_transport method calls from_env and drops the resulting client on success; that closes its file handles while leaving the environment strings unchanged. No tracked caller of require_transport was found in the reviewed tree.

These are source observations, not a producer guarantee. Do not treat require_transport as a non-consuming availability probe, and do not infer that an environment value can safely be consumed repeatedly. Before changing this adapter, identify the supported current launcher and document whether it transfers or lends the child endpoints, when each side closes them, and what repeated construction or probe behavior callers require. The reviewed tree does not resolve those questions.

## Historical native launcher: a separate ABI

A preserved historical commit contains an owner-authored native tc-proof launch path. It is linked here to retain its evidence, not to identify it as the producer for the reviewed PR38 implementation: [historical launch implementation](https://github.com/tailrocks/terminal-components-claude/blob/eff3815aae19a361fdc1016bf1ac1558dbb86047/tools/refactor-proof/src/verifier.rs#L1513-L1682) and [historical CLI entry](https://github.com/tailrocks/terminal-components-claude/blob/eff3815aae19a361fdc1016bf1ac1558dbb86047/tools/refactor-proof/src/bin/tc_proof.rs#L198-L251).

That launcher creates new request and response pipes for each launch ([pipe setup](https://github.com/tailrocks/terminal-components-claude/blob/eff3815aae19a361fdc1016bf1ac1558dbb86047/tools/refactor-proof/src/verifier.rs#L1791-L1807), [per-launch setup and protection](https://github.com/tailrocks/terminal-components-claude/blob/eff3815aae19a361fdc1016bf1ac1558dbb86047/tools/refactor-proof/src/verifier.rs#L1910-L1917)), exports the request-write and response-read descriptors with a run-bound nonce to its directly launched child, and closes its parent copies after spawn ([launch environment and post-spawn close](https://github.com/tailrocks/terminal-components-claude/blob/eff3815aae19a361fdc1016bf1ac1558dbb86047/tools/refactor-proof/src/verifier.rs#L1609-L1682)). It marks the supervisor-owned pipe ends close-on-exec so they do not survive the worker exec ([close-on-exec flags](https://github.com/tailrocks/terminal-components-claude/blob/eff3815aae19a361fdc1016bf1ac1558dbb86047/tools/refactor-proof/src/verifier.rs#L1835-L1849)). A separately launched response-provider process explicitly closes all four observer-pipe descriptors and communicates with the supervisor over its own stdin/stdout pipes ([provider setup and close loop](https://github.com/tailrocks/terminal-components-claude/blob/eff3815aae19a361fdc1016bf1ac1558dbb86047/tools/refactor-proof/src/verifier.rs#L1923-L1952)). The observer supervisor enforces the prepared per-check sequence, validates the request context, and rejects extra request bytes after the expected sequence ([sequence and EOF checks](https://github.com/tailrocks/terminal-components-claude/blob/eff3815aae19a361fdc1016bf1ac1558dbb86047/tools/refactor-proof/src/verifier.rs#L2306-L2365)). Its result-file check also rejects replay of a completed check ([launch replay check](https://github.com/tailrocks/terminal-components-claude/blob/eff3815aae19a361fdc1016bf1ac1558dbb86047/tools/refactor-proof/src/verifier.rs#L1513-L1565)).

The historical producer uses the same three environment names, but the protocol is not wire-compatible with the reviewed PR38 schema. Historical [IPC types](https://github.com/tailrocks/terminal-components-claude/blob/eff3815aae19a361fdc1016bf1ac1558dbb86047/tools/refactor-proof/src/observer/ipc.rs#L1-L67) define tc-proof-runner-observe/v1 requests binding run, task, check, request ID, operation, source commit, and tree. The historical context also binds an observer provider and a separate one-shot native-handoff descriptor. Do not bridge these protocols by dropping their identity or authority fields. The [historical runner client](https://github.com/tailrocks/terminal-components-claude/blob/eff3815aae19a361fdc1016bf1ac1558dbb86047/tools/refactor-proof/runner/observer.py#L35-L157) is the concrete Python consumer in that launch path.

The historical launch source establishes ownership for its direct child launch only. The worker-side observer descriptors intentionally survive that exec; the cited code does not establish that arbitrary later descendants close them. Its provider child has an explicit close loop, which is a separate process boundary. The historical Rust require_transport also constructs and drops the client, and no call site was found. Historical replay rejection therefore does not establish safe same-process repeated Rust construction or define a non-consuming probe contract. The original Rust safety comment claimed host ownership for the fixture lifetime; that intended ownership claim does not prove uniqueness for arbitrary safe callers. See the [historical Rust conversion](https://github.com/tailrocks/terminal-components-claude/blob/eff3815aae19a361fdc1016bf1ac1558dbb86047/tools/refactor-proof/src/observer/client.rs).

Historical [README text](https://github.com/tailrocks/terminal-components-claude/blob/eff3815aae19a361fdc1016bf1ac1558dbb86047/tools/refactor-proof/README.md#L46-L52) says runner operations require the native Rust launcher and independent response provider; direct Python bundle invocation or omission of native launch binding fails closed. This is historical documentation, not current PR38 evidence.

## Synthetic fixture: test evidence only

A separate Python fixture creates pipes and launches a sandboxed host with the request-write and response-read descriptors in pass_fds, together with its nonce. Its parent closes its copies of those child-side descriptors after the child run; a server thread owns the other two ends. The fixture’s docstring explicitly identifies it as a synthetic test authority, not the production host. [fixture authority label](https://github.com/tailrocks/terminal-components-claude/blob/5b4b9b3fae56fae096e42334ff740f67d893e82d/refactoring-tasks/terminal-components/completion/001/trusted/proof-bootstrap/host-bootstrap-observer.py#L1-L5), [worker launch/environment](https://github.com/tailrocks/terminal-components-claude/blob/5b4b9b3fae56fae096e42334ff740f67d893e82d/refactoring-tasks/terminal-components/completion/001/trusted/proof-bootstrap/host-bootstrap-observer.py#L84-L104), [pipe ownership and child launch](https://github.com/tailrocks/terminal-components-claude/blob/5b4b9b3fae56fae096e42334ff740f67d893e82d/refactoring-tasks/terminal-components/completion/001/trusted/proof-bootstrap/host-bootstrap-observer.py#L119-L166), and [driver controls](https://github.com/tailrocks/terminal-components-claude/blob/5b4b9b3fae56fae096e42334ff740f67d893e82d/refactoring-tasks/terminal-components/completion/001/trusted/proof-bootstrap/host-bootstrap-driver.py#L703-L727).

The nested build/test worker gets a fresh environment without observer variables; the fixture checks that environment fact. The second replay attempt is a new child process with new pipes but the same in-memory fixture observer and nonce. Its [replay control](https://github.com/tailrocks/terminal-components-claude/blob/5b4b9b3fae56fae096e42334ff740f67d893e82d/refactoring-tasks/terminal-components/completion/001/trusted/proof-bootstrap/host-bootstrap-driver.py#L830-L833) expects rejection after the fixture’s build/test/taskfmt sequence has already been exhausted. This test does not exercise repeated from_env construction in one process or require_transport probing, and it is not evidence of the production launcher.
