# TCC Git metadata and worktree snapshot

This directory adds Git metadata and worktree-preservation evidence to the TCC object-pack archive. It records a distinct read-only snapshot at candidate HEAD `d3546b707e980a2810cc60f8a8965ca719cbddc9`, after the five non-TCC Git-store groups were published. The branch is `parity/termrock-visual-baseline`; the active candidate worktree itself was detached at capture.

`current-d354/` contains exact common loose refs, packed refs, common reflogs, linked-worktree administrative state (excluding raw index files and local configuration), the porcelain worktree list, current ref listings, per-worktree index SHA/size metadata, and the exact selected candidate index bytes plus its stage-zero/tagged listings. The candidate index bytes match the separately sealed 561,674-byte d354 snapshot (`5e1cc0d1be38013c0844878b8b8e14d4453cb452b9304d8ea5d6f0721ffd05ea`). That d354 snapshot does not establish the other worktrees' index entries, stage flags, or extensions. `current-f763-all-worktree-indexes/` adds the exact raw bytes of all 28 currently available common Git index files and the one zero-byte `index.lock`, mapped to worktree-admin IDs and paths at HEAD `f763df0de068ef19077da841709ccc386baa98c3`. This later epoch preserves current index contents and flags without substituting them for the historical f629/c337 state. Stat-cache bytes are performance metadata; no historical byte-identical cache reconstruction is claimed.

`current-d354/historical-f629/` preserves the original f629-era ref, stash, worktree, and index/reflog inventory records as captured. The `home-inventory/` subset preserves all five data files and the original `SHA256SUMS`, which verifies successfully with the original basenames. Those records remain a separate historical epoch. The raw f629 and c337 index cache preimages were not retained, so this archive does not claim byte-identical index reconstruction, stat-cache preservation, or original sparse-index extension reconstruction. The logical stage-zero/worktree evidence and observed hashes/sizes are retained.

`canonical-worktree-closure/` preserves the sealed physical scan at d354 and its correction. The scan recorded 3,596 regular files (185,316,142 bytes) and two tracked symlinks matching the HEAD tree. The only extra ignored item was the `/target` symlink. Its exact 110-byte link text is stored as inert metadata; the external shared MBX target was not followed, copied, or recreated.

No Git configuration, hooks, credentials, or object database is included in this metadata directory. The TCC pack chunks and portable object manifest remain in the parent `tcc/` archive. This material records source custody; it does not claim that every separately inventoried local repository or external artifact has already been consolidated, remotely verified, or cleared for deletion.

The first opaque-pack GitHub tree receipt, `publication/opaque-pack-github-post-push.json`, is retained as a partial 9-of-10 file map that omitted `SHA256SUMS`. The corrected `publication/opaque-pack-github-post-push-v2.json` maps all ten blob files, including `SHA256SUMS`, at commit `f763df0de068ef19077da841709ccc386baa98c3`.
