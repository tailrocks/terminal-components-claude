# Component customization contract

This page is a source-backed contract and acceptance index for component customization. Its implementation notes are pinned to [PR38 source revision `03574346691d2367cd9ba1d6caa394025e5a2a94`](https://github.com/tailrocks/terminal-components-claude/tree/03574346691d2367cd9ba1d6caa394025e5a2a94). A source fact or existing test is evidence for the cited behavior and scope; it does not close the remaining acceptance listed in that row. The cited test bodies were inspected for this documentation change, not freshly run.

The current architecture, product, and requirements remain the shared authority: [architecture](../architecture.md), [product](../product.md), and [requirements](../requirements.md). Product appearance is governed by the retained `design/interaction-polish` reference; this page does not report a visual audit. See [theme and visual customization](theming.md) for the shared resolver and Slot contracts.

The [historical customization guide](https://github.com/tailrocks/terminal-components-claude/blob/d1122f69e6b9c2364aa6ede8174e7d35b8cfff39/docs/guides/overrides.md) is preserved for provenance. Its `junie_tui` imports and examples are not current instructions.

## Scope mechanisms

| Scope | Current source fact | Existing consumer or test evidence | Remaining acceptance |
|---|---|---|---|
| `.patch_part` | Button and Props builders accept part-specific patches ([Button](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-controls/src/button.rs#L203-L207), [PropsList and rich Props](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-controls/src/props.rs#L368-L385)). | The [Button instance test](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/tests/overrides.rs#L173-L193) changes one of three buttons and compares its siblings. Props tests exercise a part patch with theme and overlay styles ([test](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-controls/tests/props_rich.rs#L195-L255)). | Confirm builder availability, precedence, the addressed part, and sibling isolation for each component a consumer uses. The Button test exercises `.patch_part`; it does not prove every component has equivalent support. |
| `.patch` | Button and `PropsList` expose a global instance patch ([Button](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-controls/src/button.rs#L197-L201), [PropsList](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-controls/src/props.rs#L368-L372)). | The sibling integration case above uses `.patch_part`, not `.patch`. | Verify that a component’s global patch affects only that instance and has the expected merge behavior. Do not transfer `.patch_part` test evidence to `.patch` or to other components. |
| Part slots | `SlotFn<'a>` is a borrowed callback ([runtime support](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-runtime/src/support.rs#L10-L13)); Button invokes a slot for its gutter while keeping its own fill path ([Button draw](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-controls/src/button.rs#L408-L440)). | The [Button slot test](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/tests/overrides.rs#L195-L261) checks custom gutter paint, label retention, unchanged registered area and region count, hit ownership, and focus-ring reachability. | Slot behavior is component- and part-specific. Button’s container fill is not slot-substitutable. Check callback lifetime, geometry, ownership, focus, hit registration, and reference/inert behavior for each supported part. |
| Custom variants | `define_variant` merges recipe data; `override_variant` records a global override ([theme API](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/src/lib.rs#L333-L384)). | [`overrides_reach_resolution`](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/src/lib.rs#L982-L1078) exercises custom family/variant definitions and verifies a variant override does not change PRIMARY. | Preserve identifier, default-variant, selection, and unrelated-variant behavior for each real consumer. |
| Custom families and recipes | `define_family` records authored family recipe data when the edit contains parts or a default variant ([API](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/src/lib.rs#L388-L403)). An empty edit such as `define_family(f, |_| {})` is a no-op: [`AuthoredDeclaration::from_edit`](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/src/recipe.rs#L395-L418) returns `None` when neither is authored. [`Recipes::get_mut`](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/src/recipe.rs#L458-L468) separately inserts a default recipe for a missing family, but the empty edit does not reach that call. A custom family with no recipe resolves through neutral defaults ([resolver test](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/src/resolve.rs#L1887-L1911)). | Workspace consumers include [Showcase `AuthorBadge`](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/showcase-demos/src/pages/author.rs#L6-L74) and [Jackin Rain](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/jackin-preview-presentation/src/rain.rs#L46-L64). A custom-family Mono rule has a focused test ([test](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/src/downgrade.rs#L1655-L1730)). | Prove a complete independent consumer theme and its relevant roles, parts, surfaces, and Mono behavior. `Theme::from_tokens` is not a complete custom-theme constructor; see [the theming contract](theming.md#theme-shape-and-visual-scenarios). |
| `define_*` versus `override_*` | `define_*` merges authored recipe parts; `override_*` creates family/variant-wide override entries. An override may also set an explicitly authored `default_variant` ([implementation](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/src/lib.rs#L312-L403)). | The resolver tests exercise definitions, family/variant overrides, and resulting styles ([test](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/src/lib.rs#L982-L1078)); Button family and variant integration cases are also present ([tests](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/tests/overrides.rs#L67-L135)). | Select the operation by ownership and scope. Explain it using current resolver behavior; do not reuse the historical numeric precedence table. |
| Scoped overlays | `Overlay` stores a `&'static [OverlayRule]`; `Ui::with_overlay` activates an overlay for a synchronous closure and restores the stack through a guard ([overlay](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/src/recipe.rs#L692-L725), [scope](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-runtime/src/ui/mod.rs#L225-L231), [guard and call](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-runtime/src/ui/mod.rs#L279-L289), [with_overlay](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-runtime/src/ui/mod.rs#L693-L703)). | The [subtree test](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/tests/overrides.rs#L137-L171) changes one button, preserves siblings, and compares the theme fingerprint. Runtime tests cover nested and panic restoration ([tests](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-runtime/src/ui/mod.rs#L2881-L2933)). | Distinguish static rule-storage lifetime from closure scope. The runtime stack is `Vec`-backed; no unconditional zero-allocation guarantee is claimed. Preserve matching, precedence, nesting, unwind, and no-theme-mutation checks. |
| One local sibling override | A part patch can be supplied to a single component builder instance. | The [three-Button case](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/tests/overrides.rs#L173-L193) changes one Button and compares both siblings. | Keep this as a Button witness. Add a real consumer test before making the same guarantee for another component or mechanism. |
| Choosing a scope | Current mechanisms include family/variant recipes and overrides, scoped overlays, component instance patches, part patches, and supported part slots. | The source and tests linked above demonstrate selected mechanisms on Button, Props, Tabs, and two app-owned families. | Keep the advice to choose the narrowest suitable scope, paired with the per-component capability table and the precedence contract in [theming](theming.md#resolution-order). |

## Component API examples

This is a small verified sample, not an exhaustive component inventory.

| Component | Exposed builder methods at the pinned revision | Evidence and limit |
|---|---|---|
| Button | `.patch`, `.patch_part`, `.slot` ([source](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-controls/src/button.rs#L197-L212)) | Named Button behaviors are tested above. `CONTAINER` is filled by Button draw and has no slot callback path. |
| PropsList / rich Props | PropsList exposes all three; rich Props exposes `.patch_part` ([source](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-controls/src/props.rs#L368-L385), [rich builder](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-controls/src/props.rs#L1327-L1338)) | Rich Props tests exercise theme, overlay, local part patch, and four color levels ([tests](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-controls/tests/props_rich.rs#L195-L255), [tier test](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-controls/tests/props_rich.rs#L356-L381)). |
| Tabs | Global, part, and slot builders exist ([source](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-navigation/src/tabs.rs#L1284-L1297)). | Rule-policy tests check active-foreground patch authority and Reset behavior ([tests](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-navigation/tests/tabs_rule_policy.rs#L800-L858)); this does not establish every Button slot/part contract for Tabs. |

`SlotFn<'a>` is `&'a dyn Fn(&mut Ui<'_>, Rect)` ([type](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-runtime/src/support.rs#L10-L13)). Builders retain borrows of patches/part slices for their builder lifetime. This is not a stored `'static` callback or permission to retain `Ui` or frame references. Check geometry and interaction registration at the component that owns the part.

## Evidence limits

The tests linked here are source evidence, not a fresh pass receipt. The family-override integration test’s “LIST” witness resolves a `Family::LIST` label and paints text directly; it is not a live List widget witness ([test body](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/tests/overrides.rs#L87-L116)). These examples do not establish universal builder parity, visual equivalence to the design reference, or a no-allocation cost model.
