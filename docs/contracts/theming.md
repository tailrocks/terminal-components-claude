# Theme and visual customization contract

This page is a source-backed contract and visual-acceptance index. Its implementation notes are pinned to [PR38 source revision `03574346691d2367cd9ba1d6caa394025e5a2a94`](https://github.com/tailrocks/terminal-components-claude/tree/03574346691d2367cd9ba1d6caa394025e5a2a94). Source and test evidence is limited to the cited implementation and test scope; it does not prove the product’s accepted appearance. The cited test bodies were inspected for this documentation change, not freshly run. Product appearance remains governed by the retained `design/interaction-polish` reference; no visual audit or baseline change is reported here.

See [component customization](overrides.md) for the per-component availability of instance patches and slots. Current architecture, product, and requirements are described in [architecture](../architecture.md), [product](../product.md), and [requirements](../requirements.md).

The [historical theming guide](https://github.com/tailrocks/terminal-components-claude/blob/d1122f69e6b9c2364aa6ede8174e7d35b8cfff39/docs/guides/theming.md) preserves earlier scenarios and values. Its `junie_tui` examples and old numeric thresholds are not current instructions or acceptance values without a new source and rendered comparison.

## Resolution order

For `bind_defaults`, the current resolver starts with caller defaults, applies the family base and resolved variant base, then merges matching family/variant state rules. It applies capability-level profiles, Mono fallback/profile restoration where applicable, global overrides, active scoped overlays in order, and the local instance patch; semantic roles are bound after this chain. See [`bind_defaults`](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/src/resolve.rs#L836-L889), [explicit overrides and overlays](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/src/resolve.rs#L953-L980), and [role-binding test](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/src/resolve.rs#L1914-L1944).

State rules are inserted in increasing specificity, preserving declaration order among equal-specificity rules within a recipe. Family and variant state rules interleave by specificity. Ordinary equal-specificity cross-scope ordering is family before variant, with a narrow `DISABLED`/`HOVERED` exception that must remain explicit ([merge implementation](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/src/recipe.rs#L177-L259), [focused regression](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/src/recipe.rs#L1068-L1095)). These are resolver rules; they do not establish that every component exposes every override scope.

## Slot merge law and consumer interpretation

[`Slot<T>::over`](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/src/patch.rs#L7-L34) lets `Inherit` use the lower-priority value while `Set(value)` and `Clear` speak over it. [`StylePatch::merge`](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/src/patch.rs#L124-L136) applies that law per channel and resolves modifier add/remove operations; unit tests cover identity, absorption, associativity, explicit clear, and opposing modifier edits ([tests](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/src/patch.rs#L179-L225)). Recipe glyph/size slots use the same merge operation ([source](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/src/recipe.rs#L190-L218)).

`Slot::Clear` is not generally equivalent to `Color::Reset` or `Role::Custom(Color::Reset)`. The resolver binds `Set` and returns `None` for `Inherit` and `Clear` ([binding](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-theme/src/resolve.rs#L1142-L1147)); the consumer’s fallback and existing buffer/style channels still affect the result. For example, a cleared Button marker is blank ([test](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-controls/tests/button_contract.rs#L142-L162)), while the Button gutter has a component-specific pad fallback unless an explicit clear patch selects its clear-style path ([implementation](https://github.com/tailrocks/terminal-components-claude/blob/03574346691d2367cd9ba1d6caa394025e5a2a94/crates/termrock-controls/src/button.rs#L425-L442)). Preserve Set, Clear, and Reset as distinct authoring cases and document rendered behavior per consumer.

## Concern ownership

Shared theme types own reusable semantic color roles, design tokens, recipes, glyphs, borders, motion, density, and capability behavior. Application consumers can define app-owned families and select instance/scope styling where the component exposes it. Preserve the dependency boundary and implement application-specific appearance in application theme setup where supported. This architectural responsibility does not itself prove a widget’s public builder, a downstream theme, or visual parity.

## Acceptance boundary

Keep all twelve scenarios, resolution order, Slot law, and concern ownership as independent requirements. Source facts, existing named tests, independent-consumer behavior, and rendered comparison against `design/interaction-polish` are different evidence classes. The links identify existing source/test bodies; this documentation change does not assert that those tests were rerun or that their scenarios are complete. No historical color threshold, palette value, downgrade equivalence, or reset/mono output is promoted to current acceptance without a source-qualified consumer and rendered comparison.
