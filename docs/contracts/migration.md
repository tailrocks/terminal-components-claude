# Migration contract for the split workspace

This is a historical-concept crosswalk, not a step-by-step porting recipe. Current source and evidence references are pinned to [`54daace12e750db17ca785f2a076e8fd2266d5ae`](https://github.com/tailrocks/terminal-components-claude/tree/54daace12e750db17ca785f2a076e8fd2266d5ae). The earlier guide and code remain at immutable [`d1122f69`](https://github.com/tailrocks/terminal-components-claude/blob/d1122f69e6b9c2364aa6ede8174e7d35b8cfff39/docs/guides/migration.md); its monolithic package paths, imports, examples, and checkmarks are historical, not current package instructions or proof.

The current workspace and its broad migration gates are described in [architecture](../architecture.md), [requirements](../requirements.md), and the [application acceptance plan](../plan.md). Each retained prerequisite below must still be mapped to a current consumer or focused test. Crate presence, compilation, or an old “implemented” mark does not close a semantic contract. The [component authoring map](authoring.md) records selected current-source and consumer evidence; its named cases are not a fresh test-pass receipt.

## Verification rule

For each retained prerequisite, record the exact current source and a consumer or focused test, then identify any unproved states or routes. Compare output with the retained `design/interaction-polish` reference through its separate visual process. Compilation, a source symbol, a named unit case, or a historical “implemented” label does not establish compatibility, completion, or visual parity.
