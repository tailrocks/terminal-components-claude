Form owns submission interaction in update: it commits the focused draft, clears stored errors, checks shown fields in declaration order until the first failure, and runs whole-form validation only when those field checks succeed. A failure records the error, requests reveal and focus, and emits `Invalid`; success emits the configured action identity. Values remain caller-owned through `FormData`, and `draw` receives shared state/data references. This is why Form is an interaction component rather than only a drawing/layout helper ([`FormData`](https://github.com/tailrocks/terminal-components-claude/blob/88b3ef1aef45720bd4f3bbb07eb9672b78f5487f/crates/termrock-forms/src/form.rs#L199-L230), [submit path](https://github.com/tailrocks/terminal-components-claude/blob/88b3ef1aef45720bd4f3bbb07eb9672b78f5487f/crates/termrock-forms/src/form.rs#L1560-L1606), [update call](https://github.com/tailrocks/terminal-components-claude/blob/88b3ef1aef45720bd4f3bbb07eb9672b78f5487f/crates/termrock-forms/src/form.rs#L1741-L1745), [draw](https://github.com/tailrocks/terminal-components-claude/blob/88b3ef1aef45720bd4f3bbb07eb9672b78f5487f/crates/termrock-forms/src/form.rs#L1925-L1931); [checked-in controls](https://github.com/tailrocks/terminal-components-claude/blob/88b3ef1aef45720bd4f3bbb07eb9672b78f5487f/crates/termrock-forms/src/form.rs#L5480-L5540)).

## Verification rule

For each retained prerequisite, record the exact current source and a consumer or focused test, then identify any unproved states or routes. Compare output with the retained `design/interaction-polish` reference through its separate visual process. Compilation, a source symbol, a named unit case, or a historical “implemented” label does not establish compatibility, completion, or visual parity.
