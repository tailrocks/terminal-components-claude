# Component authoring

This page is a source-and-evidence map for the public authoring surface. The existing public-surface and consumer rows retain reviewed source snapshot [`54daace12e750db17ca785f2a076e8fd2266d5ae`](https://github.com/tailrocks/terminal-components-claude/tree/54daace12e750db17ca785f2a076e8fd2266d5ae); relative source links in those rows are interpreted in that review scope. The current-owner guidance added below is bound to [`f4611b1fe98a98b78c9e2c32a6c9522fe72fd863`](https://github.com/tailrocks/terminal-components-claude/tree/f4611b1fe98a98b78c9e2c32a6c9522fe72fd863). The source and test bodies cited here were inspected for this documentation change; they were not freshly executed. This is not a copy-ready tutorial or a declaration of complete API compatibility.

## Consumer status

The workspace includes an isolated [`termrock-consumer-example`](https://github.com/tailrocks/terminal-components-claude/tree/54daace12e750db17ca785f2a076e8fd2266d5ae/crates/termrock-consumer-example). Its manifest is `publish = false`, has `termrock` as its only normal dependency, and uses Ratatui only as a dev dependency. Its source and integration tests exercise shared composition, caller-owned recipe data, typed keyboard and pointer actions, a narrow layout, and repeated rendering through the public facade. This is a workspace-isolated consumer and source-inspected integration coverage. It is not a separately maintained or published third-party crate, a fresh test-pass receipt, proof of every component contract, or a public-version stability guarantee.

## Current public surface

The [`termrock` facade](../../crates/termrock/src/lib.rs#L61-L80) re-exports selected runtime-authoring, identity, input, response, focus, hit, layout, text, collection, and theme types. The `termrock::author` surface is supported by [`termrock-runtime::author`](../../crates/termrock-runtime/src/author.rs). Use the facade or its declared authoring exports in a consumer; do not copy the obsolete `junie_tui::author` imports or the removed monolithic example from the [historical authoring guide](https://github.com/tailrocks/terminal-components-claude/blob/d1122f69e6b9c2364aa6ede8174e7d35b8cfff39/docs/guides/authoring.md).

## Component owner checklist and evidence

Document each public component at its owner: construction and configuration; owned state and borrowed inputs; variants, states, and actions; keyboard, pointer, and focus behavior; layout and parts; override points; identity rules; tests; and invariants. Keep examples complete and runnable against current `termrock` facade signatures, explain stable identity, and state why captures remain borrowed. For every migrated assertion, name its current source/test successor or explain why the assertion no longer applies; a source locator is not a pass or coverage count.

[`Brand`](https://github.com/tailrocks/terminal-components-claude/blob/f4611b1fe98a98b78c9e2c32a6c9522fe72fd863/crates/termrock-controls/src/brand.rs#L330-L363) is a useful example: source tests check clickable hit and `LABEL` registration without making the mark a tab stop, press-versus-release activation, and actual accent/hover output while a plain lockup remains on the accent plane ([input](https://github.com/tailrocks/terminal-components-claude/blob/f4611b1fe98a98b78c9e2c32a6c9522fe72fd863/crates/termrock-controls/src/brand.rs#L366-L404), [painted accent](https://github.com/tailrocks/terminal-components-claude/blob/f4611b1fe98a98b78c9e2c32a6c9522fe72fd863/crates/termrock-controls/src/brand.rs#L469-L504)). The disabled rule also has an explicit Junie/Paper comparison across TrueColor, ANSI256, ANSI16, and Mono, with disabled-only versus disabled+hover ink ownership checked; conformance independently compares the rendered states ([theme rule](https://github.com/tailrocks/terminal-components-claude/blob/f4611b1fe98a98b78c9e2c32a6c9522fe72fd863/crates/termrock-theme/src/builtin/mod.rs#L907-L950), [control conformance](https://github.com/tailrocks/terminal-components-claude/blob/f4611b1fe98a98b78c9e2c32a6c9522fe72fd863/crates/termrock-conformance/tests/control_states.rs#L652-L662)). These are source-mapped test bodies, not fresh pass evidence.

## Total clipped composition

A composed overlay preserves its semantic surface and caller styling while clipping child painting and registrations. It runs an `FnOnce` body exactly once even when body geometry is empty and returns that value; an empty clip does not skip traversal. The current Dialog body-slot adapter delegates through `Dialog::draw` ([adapter](https://github.com/tailrocks/terminal-components-claude/blob/f4611b1fe98a98b78c9e2c32a6c9522fe72fd863/crates/termrock-overlays/src/dialog.rs#L1334-L1349)). Its zero/small-geometry test checks result `42`, one invocation, the Elevated surface, and no escaped paint or registration; the adjacent drawable case checks chrome and body clipping ([total-body test](https://github.com/tailrocks/terminal-components-claude/blob/f4611b1fe98a98b78c9e2c32a6c9522fe72fd863/crates/termrock-overlays/src/dialog.rs#L1652-L1706), [drawable case](https://github.com/tailrocks/terminal-components-claude/blob/f4611b1fe98a98b78c9e2c32a6c9522fe72fd863/crates/termrock-overlays/src/dialog.rs#L1710-L1755)). Keep the full sentinel, part/surface, and visual matrix as separate evidence.

## Prepared-frame consumer sequence

At the terminal boundary, read the current terminal area, call `prepare`, project that exact token with `draw_prepared`, and acknowledge it only after terminal `try_draw` succeeds. `prepare` may initialize and settle runtime work before retaining output; `draw_prepared` validates token and area and projects without re-running application code. An area change requires a new preparation. Keep semantic state changes in `update`; drawing may still register runtime state or diagnostics, as noted above. The current flow is in [runtime preparation/projection](https://github.com/tailrocks/terminal-components-claude/blob/f4611b1fe98a98b78c9e2c32a6c9522fe72fd863/crates/termrock-runtime/src/runtime.rs#L1994-L2079) and [session transport/acknowledgement](https://github.com/tailrocks/terminal-components-claude/blob/f4611b1fe98a98b78c9e2c32a6c9522fe72fd863/crates/termrock-session/src/session.rs#L649-L678).

## Evidence boundary

The public consumer has selected layout, keyboard, pointer, narrow-size, deterministic-render, and action/repaint cases. The conformance harness checks repeat draw, semantic state stability, draw bounds, and tiny rectangles only for registered cases and supported capabilities. A facade export, crate manifest, macro, or source signature is not proof that every component satisfies those contracts. Keep focused component tests separate from real consumer journeys and visual comparisons.

Use [component contracts](../components-contracts.md) for the acceptance index, [migration](migration.md) for retained semantic requirements, and the maintained [customization](overrides.md) and [theme](theming.md) pages for style scopes, precedence, Slot laws, and color-capability scenarios. These customization pages retain their own older source pins and evidence limits; their presence is not a fresh audit of this source snapshot.
