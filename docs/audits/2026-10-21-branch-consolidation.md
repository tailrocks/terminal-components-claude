## Scope

tip; it never writes to the shared parity branch.

## How each branch was measured

For every branch:

1. `git rev-list --count origin/parity/termrock-visual-baseline..origin/<branch>`
   counts the commits the branch has that the tip does not.
2. `git diff --name-only origin/parity/termrock-visual-baseline...origin/<branch>`
   lists the files the branch's own commits touch.
3. For each of those files the branch blob and the tip blob are compared with
   `git rev-parse --verify`. A file that is byte-identical is present. A file
   that differs is compared with `git log -1` on both sides to see which side
   carries the later commit, which tells a newer tip evolution apart from a
   newer branch evolution.
4. `git cherry` gives the patch-id view of the same question.

The verdict is taken from the file-level content, not from the branch name and
not from the patch-id alone. A branch whose commits are already reachable from
the tip is "already integrated"; a branch whose files are all present in the
tip at the same or a newer evolution is "superseded"; a branch that still
carries a capability the tip lacks is "merged" or "conflict".
