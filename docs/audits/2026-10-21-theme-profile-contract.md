# Theme variant and surface profile contract (increment 1)

This increment extends the existing capability-specific family recipe resolver. It does not change Junie palette/profile declarations or approve any visual output. The fixed product revisions remain baseline source `4169783ae883788186d161af09ba9c481bd84e5c`, baseline tag object `2718a6b8127a522a3d351d0b4bdb7542fc8da542`, design source `f4867e9b5f8a08a3bb61ce80d644198a29f51984`, and tuiscotti `a1ea27f757d75d07b05499276cd932e9f8e067ad`. No source reference changed.

The read-only repair plan was `button-theme-repair-plan-5f82c4d/report.md`, SHA-256 `ebeda9daa7c902c839174d6444a61b9d814453fcaf25b6b30296369ce227d6af`. The source work extends `Recipes`/`StyleCache` rather than introducing another resolver. Existing `define_family_for_level` remains available. New public adapters key defaults by resolved variant, and optionally by the surrounding `Surface`; resolution composes family, variant, then variant-plus-surface profile defaults before ordinary global, scope, and instance overrides. Existing family-profile behavior is covered by the `SPLIT` tests listed below.

Profiles record both source and level-projected color-token snapshots. This handles consumers that select a capability by setting it directly while keeping source tokens, and consumers that use `for_level`/`downgrade` and project the tokens. Profile eligibility checks semantic-role dependencies per channel, so changing an unrelated token does not invalidate unrelated authored profile channels. The style cache incorporates surface and only the current semantic tokens referenced by the active profile seed; its dependency fingerprint is computed without allocating a token vector. Mono resolution restores channels explicitly supplied by an active profile after the existing generic fallback, then leaves later explicit overrides in the existing precedence path. No raw color conversion algorithm or quantizer was modified.

The public consumer tests use a custom family and different data alongside a real `termrock_controls::Button` drawn through `Runtime`/`Ui`. They cover default-variant remapping, variant and family separation, surface separation, direct semantic token mutation and cache invalidation, same-valued `Role::Custom` override, ordinary override precedence, `Set`/`Clear` across foreground, background, underline, glyph, size, alignment and modifiers, and Mono fallback precedence where authored rules win profile defaults. It adds no Junie color constants and does not alter the 73-slot oracle. The showcase API catalog entry for the two new public adapters remains outstanding and must be handled by the integration owner because this increment owns only Theme APIs, focused tests, and the audit.
