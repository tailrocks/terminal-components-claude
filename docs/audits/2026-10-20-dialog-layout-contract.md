# Dialog layout contract repair

## Scope and source evidence

The work began at candidate revision `39aaf8d5e1dab5cf1c613c0bb7e76638d89d57af`. Frozen reference arithmetic is in [`src/widgets/dialog.rs` at baseline commit `4169783ae883788186d161af09ba9c481bd84e5c`](https://github.com/tailrocks/terminal-components-claude/blob/4169783ae883788186d161af09ba9c481bd84e5c/src/widgets/dialog.rs): `chrome_rows` returns `5 + 2 * pad.y` (lines 887–903); `height` adds wrapped body rows, fixed rows, and `action_rows` (lines 1310–1329); draw places content inside border plus configured horizontal/vertical padding and starts the body two rows below the title (lines 1304–1329). These values define the frozen layout contract for the candidate tests.

## Candidate repair

[`crates/termrock-overlays/src/dialog.rs`](../../crates/termrock-overlays/src/dialog.rs) now uses one `DialogLayout` for measurement, drawing, body clipping, title/detail bounds, input bounds, and action bounds. The resolved viewport width is used before layer measurement so a dialog configured wider than a narrow terminal measures its wrapped action rows at the visible width. A zero-width bootstrap viewport retains the configured width until a real viewport is available. Frozen vertical padding and title/action gaps are restored at normal sizes; constrained short frames shed padding and retain the title before allocating available action rows, preventing overlap. Excess actions remain capped at `Dialog::MAX_ACTIONS`; no action may register outside the clipped frame. Empty body callbacks remain total.

The previous worker commit `23f911902` is superseded for this file. Its two audit claims that body height and title positioning matched the frozen contract were incorrect: it omitted the frozen vertical pad/title gap, calculated action wrapping at configured rather than resolved viewport width, and allowed action rows to consume the title row in a short terminal. Those defects were reproduced by independent probes in `/tmp/termrock-dialog-layout-probes-23f911902/src/lib.rs` (narrow `20x40` viewport with configured width 60 and eight actions; `16x4` two-action view; title-only measured-height view). The superseding implementation adds corresponding regression tests, plus narrow-view action-cap coverage.

Review of `9c64f948` found a further width mismatch: measurement used configured shortcuts while layer sizing and drawing used effective keymap bindings. A remapped `F12` shortcut could add an action row after measure allocated a height, clipping a description. Measurement, layer sizing, and draw now resolve effective shortcut widths through the same helper; measure uses the current `Ui` keymap without running input handlers. The red-before fix review probe is preserved at `/tmp/termrock-dialog-layout-probes-9c64f948/src/lib.rs`; all eight probes pass against this worker tree via a copied manifest at `/tmp/termrock-dialog-layout-probes-current`.

Several old compact measurement assertions in the candidate were stale when compared to the pinned baseline formulas above. They now assert the frozen chrome/body arithmetic and compare prompt measurement with the same title/actions without an input. The body-growth test uses a `40x24` viewport so the layer resolver does not clamp its measured height; it asserts the five visible body rows contribute five rows. This is a test correction derived from frozen source arithmetic, not a candidate golden or a reference artifact change.
