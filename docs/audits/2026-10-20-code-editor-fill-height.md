# CodeEditor fill-height contract

The frozen source commit `4169783ae883788186d161af09ba9c481bd84e5c` renders `CodeEditor` into its complete allocated rectangle: `src/widgets/code.rs` intersects the caller's area with the buffer, derives the body from `area.height`, and sizes the text viewport from that body. The split editor API instead limited draw height to `CodeEditor::new(id, rows)` and measured the configured row count. Flexible compositions therefore had no shared way to give an editor the remaining vertical space.

`CodeEditor::fill_height(true)` now makes measurement prefer the supplied height constraint and makes draw consume the allocated height. The default remains row-limited. `fill_height(false)` restores that limit, including after a caller reuses the builder configuration. Drawing continues to derive its body, text hit region, focus bounds, cursor, clipping, and scroll viewport from one returned editor rectangle. Measurement accepts only `Ui` and constraints and does not mutate editor state.

The compiled integration consumer uses independent long SQL-like text with wide and combining Unicode, checks measured and drawn heights, click routing into the last allocated text row, focus bounds, cursor containment after resize, the unchanged row-limited default and explicit reset, empty content, and a zero-sized allocation. A focused unit check covers loose, tight, and zero-height measurement. `cargo nextest run --locked -p termrock-editors` passed all 53 tests, including four new fill-height tests. Strict package Clippy passed. Workspace `cargo fmt --all -- --check` remains red on pre-existing formatting in Showcase and TablePro; the two changed Rust files were formatted directly. No application or expected-reference source changed. This API contract does not establish any application's paired frozen-CLI parity; consumer adoption and paired verification remain required.
