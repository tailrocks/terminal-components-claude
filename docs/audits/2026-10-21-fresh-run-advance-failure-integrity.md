# Fresh-run advance failure integrity

This audit covers the bounded runner change based on PR #38 plus `310a56de62e0d2e87a647ffd58b9b5cec9c0a744`. It does not authorize or perform a real baseline capture.

`advance_fresh_run` previously renamed a completed attempt directory to its final chunk name, cleared the attempt handle, then verified the published tree and wrote the immutable journal receipt. A verification or receipt-publication error in that interval left an unreceipted final chunk, no failure marker, and no safe retry path.

The runner now validates the frozen staged tree before publication, keeps the attempt identity until the journal commit point, and validates all already journaled chunk artifacts before starting a later chunk. If final-tree validation or receipt publication fails before an immutable ordinal receipt exists, it restores the chunk to its original `.attempt-*` path and publishes an `untrusted-failure.json` marker. Captured files remain byte- and mode-preserved; only the owned attempt directory mode may be made writable to publish the marker. If an append raises after the exact signed receipt was already published, the runner validates that receipt and its artifacts, leaves both immutable objects untouched, writes an external `failed-attempts` marker, and returns an error. Further advancement is blocked while such a marker exists; the receipt is evidence that the ordinal committed, not evidence that the command returned normally. No candidate eligibility or product acceptance is inferred.

Focused regressions cover child failure and timeout through `advance_fresh_run` and the real `run_live_chunk`/`run` process boundary using a task-owned fake `cargo` executable; artifact mutation; post-rename verification failure; journal failure before publication; and an exception after exact immutable receipt publication. Failed pre-commit runs retain their attempt, process logs, and report, return no successful output, and validate at ordinal zero. A later successful retry uses that same ordinal. The timeout case invokes the actual subprocess timeout and process-group cleanup path. Post-publication failure preserves the exact receipt and tree hashes, authenticates the truthfully completed ordinal, and blocks automatic next-ordinal execution until a separately verified resume is implemented. Other verification/journal boundaries are injected at the trust boundary and are not represented as end-to-end external runner fault injection.

Validation: `python3 -m py_compile tools/frozen_baseline.py tools/test_frozen_baseline.py`; all five focused `RunnerGuards.test_fresh_advance_*` regressions passed; `python3 tools/test_frozen_baseline.py` passed 75 tests; `git diff --check` passed. The full frozen application capture/replay, reference approval, candidate comparison, and acceptance gates remain unrun and incomplete.
