# Picker family contract increment (2026-10-20; in progress)

This increment moves query editing for `FilterList` and `Picker` onto the shared `TextInput`/`TextInputState` editor core, adds case-insensitive contiguous substring filtering without changing the existing fuzzy `Label` policy, makes the picker row cap explicit (`max_rows`, default 12), and supports reverse scope navigation with BackTab. An external consumer test exercises stable domain item keys through the public API.

The query field now uses the shared text editing path for grapheme-aware insertion/deletion, caret movement, paste, selection state/rendering, and horizontal scroll. Its editor response is folded into the list response so caret-only motion and selection repaint correctly. A hidden `TextInput::style_target` adapter maps the shared field renderer through Picker's `Family::PICKER` / `Part::QUERY`; global, part-specific, theme, placeholder, focus, and disabled styles continue through the shared resolver. Query layout and drawing continue through the existing Picker/FilterList render path. Focus-owner registration is singular for searchable pickers.

The fields follow-up (initially pushed as `dd9836a2`) adds the public `TextEditCommand`, `EditCapabilities`, and `EditMenuRequest` API, one shared executor for TextInput and TextArea, keyboard and secondary-click menu requests, and grapheme-safe pointer selection (single click, word, line, and drag). Follow-up runtime tests exercise copy/cut/paste/select-all, secret and disabled rejection, idle paste initialization, menu request anchoring, pointer drag and scrolled caret placement. Independent review found idle Paste draft initialization, ordinary-string clipboard temporaries, SelectAll repaint reporting, and doubled horizontal scroll defects. The follow-up fixes them by initializing sensitivity before command mutation, using a zeroizing `Secret` clipboard temporary, measuring selection change directly, and sharing one command executor across both fields. These fixes and regression tests passed `cargo nextest run -p termrock-fields --lib` (50/50), fields clippy, scoped rustfmt, and `git diff --check` before commit.

The final field follow-up also aligns secondary-click preparation with the frozen edit-menu contract: it starts the shared editor, focuses the field, maps the pointer through the field viewport, places the caret unless the pointer is inside an existing selection, then emits the menu request. Idle read-only fields expose Select All from committed content; execution initializes the sensitivity-correct editor before selecting, allowing a subsequent Copy while retaining selection rendering. Runtime tests cover TextInput and TextArea right-click paste at the clicked location, selection preservation, and idle read-only Select All/Copy. These are field-level regressions only; the picker overlay has not yet consumed the request API.

## Runtime-layer field port (2026-10-20)

The reviewed field command executor and pointer-selection changes were ported onto runtime prepared-frame commit `29d07015ae9a19bb282e30f48c1876ff15a8fc9e`. `EditCapabilities::editable` now reports editability separately from copy/select-all availability; disabled fields reject paste. Hosted query styling maps only the field surface and text to Picker's `QUERY` token. Gutter, placeholder, and selection retain independently resolvable field parts. Regression coverage includes those part styles and idle read-only capabilities. Focused validation on this port passed `cargo nextest run -p termrock-fields --lib` (54/54), `cargo clippy -p termrock-fields --all-targets -- -D warnings`, edition-2024 rustfmt, and `git diff --check`.

Exact-opening field focus continuation remains incomplete. Runtime entry validation and acknowledgement exist in `29d07015`, but a field-owned outcome for successful restoration versus cancellation still needs a runtime query bound to the owner and exact opening. The overlay owns and consumes its edit-menu command completion; fields do not consume it. This work does not use application-level `BlurPolicy::Keep` to approximate temporary focus retention. Record the continuation lifecycle as blocked until the runtime contract lands and field tests cover return, redirect, cancellation, superseding focus, and exactly-once blur.

## Remaining contract gap

The frozen baseline picker (`src/widgets/picker.rs` at baseline source commit `4169783ae883788186d161af09ba9c481bd84e5c`) integrates `EditMenu` through `edit_menu_key`, `edit_menu_pointer`, `edit_menu_route`, and `point_field`. The shared fields now expose the menu request and command execution contract, but the overlay adapter and Picker query routing are still not connected. Overlay focus retention and repeated open-close behavior also remain unverified. This increment therefore does not establish complete picker interaction parity and must not be reported as a completed picker contract.

Next, connect the shared field menu request and command APIs to the reusable overlay adapter, then route Picker query pointer events through that API while preserving one query owner and editor state/cursor. Test overlay focus retention, click and drag selection, menu actions, Home/End, Escape clear-then-close, and outside-dismiss focus restoration through the runtime. Then run paired baseline/candidate CLI checkpoints with pinned tuiscotti before claiming parity.
