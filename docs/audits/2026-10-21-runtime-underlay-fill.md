## Superseded finding

Its underline-color fix was valid for a single overlay, but its claim that nested overlays already preserved the nearest lower-layer ink was incorrect. The original nested test ignored a failed `Runtime::handle(Tick)` and never opened its upper layer. The same independent review found that page fill could retain `ForcedWidth(4)` when replacing a wide symbol with a space. That defect also reproduced on both revisions.

## Current implementation

`LayerDraw` now carries a private per-cell style intent for underlay fills. The existing ascending layer compositor resolves that intent against the live destination after lower overlays and the layer backdrop have been applied. It inherits unmodified foreground, underline color and modifiers, plus foreground/background semantic roles. Tracked paints and explicit style patches accumulate channel and modifier operations; raw full-cell writes cancel the intent. `move_cell` transfers it with cell data and roles. Ordinary cells without intent keep the prior complete-cell copy path.

Page fill is immediate: it snapshots foreground/underline/modifiers, resets symbol and transport metadata, emits an ordinary space, and replaces the background. Layer fill emits a reset ordinary space and records only its explicit background before deferred composition. Both paths reset wide/skip transport metadata and respect the active clip. No public API, application, menu, theme, or input-dispatch code changed.

The invalid old unit expectation that a layer closure can observe inherited page ink was updated: it now asserts placeholder state before composition and inherited state after composing against the actual page.

## Follow-up independent review and repair

The independent review of `bb012956690d08381b16aa28985b474ad7501d1c` accepted the nearest-layer/underline/role and ordinary-width fixes, but found three regressions in full public-runtime frames: `scroll_edges` changes ink after fill and that fade was lost at composition; `Style.add_modifier` plus `sub_modifier` overlap had the inverse precedence of Ratatui's remove-wins `Cell::set_style`; and `move_cell` left inherited underline/modifier intent on its vacated source although the source cell had been reset. The unchanged review consumer's three fixtures are preserved under `postfill_scroll_fade_is_not_overwritten_by_composition`, `overlapping_modifier_fields_keep_ratatui_remove_precedence`, and `moved_label_vacated_cell_uses_explicit_reset_attributes` in `tests/underlay_stack.rs`.

The layer now defers scroll-edge fading only for underlay-intent cells and evaluates it against the final composed foreground, background and modifiers. The scroll regression has a distinct page foreground (red), lower-layer foreground (blue), and a green explicit glyph, then compares the underlay upper layer's result to an upper layer painted with the actual lower blue. It demonstrates that the fade uses deferred lower-layer ink, not the page placeholder. The usual direct paint path is unchanged. Tracked Ratatui paint operations use remove-wins for overlapping modifier masks; explicit `StylePatch` continues to use its remove-then-add order. A vacated moved cell records a complete underline/modifier reset while retaining its foreground/background and role behavior. Deferred state is stored sparsely in an optional map: ordinary layers allocate no intent storage, and only underlay-filled cells receive entries. The compositor avoids cloning the destination cell when a source cell has no underlay intent.

## Ordered-operation follow-up

The independent review of `5ac1ae24b9f0548bc064d6609de26245e62695ea` (packet `runtime-underlay-5ac1ae24-independent-review-20261021/review.json`, SHA-256 `95db7806e8092f26a364959aea39f73d54163a0b7be4a1b1d5e86c235d6ec708`) found that a single deferred fade and post-hoc modifier/channel aggregation did not preserve supported painter call order. It supplied public-runtime differential cases for remove-wins overlap against inherited BOLD, background and REVERSED changes after fading, and repeated RGB fading. These were kept as consumer tests and extended with fade-then-remove-DIM, explicit foreground, and semantic foreground patch cases.

`CellUnderlayStyle` now keeps an ordered list of private paint, patch, fade, and source-reset operations. Composition starts from the nearest actual lower-layer cell, substitutes the explicit fill background (and its role replacement), then replays those operations in order. This preserves Ratatui paint remove-wins behavior and `StylePatch` remove-then-add behavior without guessing from color differences. The existing sparse optional map remains lazy; the no-intent compositor path avoids cloning the destination cell. No performance benchmark was run, so this is only a structural fast-path claim. A focused internal test caught that the replacement background must clear the inherited background semantic role; that role replacement is now explicitly asserted by the existing compositor test.
