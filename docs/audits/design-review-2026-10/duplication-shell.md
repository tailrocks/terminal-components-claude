Read-only review of the four app shells (`src/bin/*/app.rs`, `main.rs`) for logic implemented more than once. Recorded 2026-10-16. The consolidated decisions and the execution order are in [`docs/architecture/shared-components-plan.md`](../../architecture/shared-components-plan.md).

Worktree add was killed, dir removed, `git worktree prune` run. No repo edits; `visual-baseline` untouched; no tests run.

**Shell size:** `app.rs` + `main.rs`: showcase 1651+153, tablepro 2841+160, holla 3575+180, jackin 2838+163, ≈11.5k lines. Most is shell plumbing. Paths below are relative to `src/bin/`. S = showcase, T = tablepro, H = holla, J = jackin_preview.

## Proposed app shell

**The library owns** a new `junie_tui::shell` module:
- **Runtime glue:** `Shell<A: App>` implements `runtime::Application`.
- **State:** `Focus`, `FocusRing`, `HitRegistry`, `PointerRouter`, `KeyRouter`, `ShellLayers`, `Router<R>`, `StatusLine`, `Footer`, `Chrome` (menu bar, tab strip, too-small), `Clock`, `Motion`, `Clipboard`, quit flow.
- **Behaviour:** render prologue and epilogue, focus fallback, blur fan-out, the help overlay derived from keymaps, and `CommonArgs` / `run`.
- **Widgets:** every library modal implements `Layer`; every interactive widget implements `MouseTarget`.

**A consumer app writes only this:**
```rust
#[derive(Parser)] struct Cli { #[command(flatten)] common: CommonArgs, #[arg(short, long)] scenario: Scenario }

impl shell::App for Holla {
    type State = World; type Route = Route; type Cmd = Cmd;
    fn tick(&mut self, s: &mut World, clock: &dyn Clock) -> Vec<Msg>;        // domain only
    fn on_command(&mut self, cmd: Cmd, s: &mut World, cx: &mut Cx) -> Outcome;
    fn quit_guard(&self, s: &World) -> Option<ConfirmSpec> { … }
    fn chrome(&self) -> Chrome<Cmd> { Chrome::menu_bar(menus()).tabs(TabPolicy::Closable).status_segments(seg) }
}
fn main() -> io::Result<()> {
    let cli = Cli::parse();
    Shell::builder(Holla::new(cli.scenario))
        .name("holla").brand(BRAND_MARK).min_size(72, 20)
        .routes(routes! { Route::Finder => FinderPage::new, Route::Files => FilesPage::new, … })
        .keys(ShellKeys::default().quit(ctrl('q')).force_quit(ctrl('c')).help([F(1), '?']))
        .pointer(PointerConfig::DEFAULT).context(ContextConfig::DEFAULT)
        .clock(SimClock::new(EPOCH)).motion_env("HOLLA_NO_MOTION")
        .run(cli.common)
}
```
Pages implement `shell::Page<World>` (render, keymap, hints, key and mouse hooks, `on_layer_result`) and nothing else. No app holds `Focus`, `PointerState`, a `Modal` enum, `on_mouse`, a footer, or a help table.

**Migration order** (visual suite after each step, `cargo nextest`):
1. `CommonArgs`, `Motion`, `Clock`, `StatusLine`, `TooSmall`, render prologue.
2. `Layer` on library modals plus `ShellLayers`.
3. `MouseTarget` plus `PointerRouter`.
4. A single `Page` trait (S through a `PageEvent` adapter; T split into two pages).
5. `KeyRouter`, `ShellKeys`, derived help.
6. `Footer` composition.
7. `Router`/tabs, `Chrome` menu bar, context menus, `QuitGuard`, `Clipboard`.

Each step deletes the matching rows above in all four apps together. Drift gets decided once, in the library defaults: Press focus, 5 s status on the shell clock, Ctrl+C = interrupt then force quit, F1 and `?` for help, `Reduced` motion everywhere, auto "Tab Next" with de-duplication. Estimated removal: about 4.5–5k lines from the four `app.rs` + `main.rs`.
