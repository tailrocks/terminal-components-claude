Some shared code already exists and should be built on rather than replaced: `ScrollState`, `RowSelection`, `TypeAhead`, `NavKeys`, `Dismiss`/`Place`/`Frame`, and the traits `ContextSource`, `Modal`, `BlurTarget`, `PointerField` and `Actions`. The problem is uneven adoption.

**Proposed composable architecture**

1. **One event shape.** `enum UiEvent<'a> { Key(Key), Paste(&'a str), Pointer(PointerEvent), Wheel{part: Part, dx:i32, dy:i32, mods}, Blur(FocusChange), Dismiss(Dismissal) }`, built by the runtime dispatcher from `Input`, `PointerState` (click count, flash) and `HitRegistry::resolve`. Widgets never see raw ids or `MouseKind`.

2. **Core traits every widget implements:**
   - `trait Component: Render { type Event; fn id(&self)->WidgetId; fn handle(&mut self, ev:&UiEvent, cx:&mut EventCx) -> Response<Self::Event>; }`
   - `Render` and `Measure` as described in the table.

3. **Opt-in capability traits.** Each has default methods, so a widget composes a shared struct and exposes an accessor:
   - `Scrollable { fn pane(&mut self)->&mut ScrollPane }`. The dispatcher sends `Wheel` and `Part::Bar` here before `handle`.
   - `Navigable { fn cursor(&mut self)->&mut Cursor; fn rows(&self)->&dyn RowSource }`. It handles Nav, type-ahead and `ensure_visible` through the pane.
   - `Selectable { fn selection(&mut self)->&mut RowSelection; fn click_policy(&self)->ClickPolicy }`
   - `Editable { fn field(&mut self)->&mut EditField }`. Paste, PointerField and blur commit go through this.
   - `HasHints`, `ContextSource`, `Overlay`, `Focusable { fn focus_policy(&self)->FocusPolicy }`.

   The dispatcher runs this chain:

   ```
   chord guard → Overlay(dismiss) → Scrollable(wheel/bar) → Editable → Navigable → Selectable(click/gesture) → Component::handle(rest)
   ```

   Because the chain is shared, one interaction cannot behave differently in two widgets. `handle` only sees what is specific to the widget: domain events such as sort, follow-reference, expand or close-tab.

4. **Shared building blocks** that widgets embed instead of copying: `ListCore { cursor: Cursor, pane: ScrollPane, selection: RowSelection, typeahead: TypeAhead, reveal: Reveal, content: ContentState }`, `RowPainter`, `EditField`, `OptionList`. For example:
   - ListBox, Tree, Props and Steps are `ListCore` plus a row renderer.
   - Table and Grid are `ListCore` plus columns plus a cell `EditField`.
   - Select, Picker, Completion, ContextMenu and OptionEditor are chrome around `OptionList`.

5. **Containers.** `trait Container: Component { fn visit(&mut self, f:&mut dyn FnMut(&mut dyn AnyComponent)); }`, where `AnyComponent` is an object-safe erasure that boxes events into `Box<dyn Any>`.
   - **Focus:** the ring is the order of `RenderCx::control` registrations (unchanged). Tab and Shift+Tab are handled by the runtime. `Focusable` lets a container act as one stop or pass focus through.
   - **Hit:** registrations are tagged `{owner, Part}`. A pointer event goes to the owner. If it returns `Ignored`, it bubbles up the parent chain recorded at render time (`RenderCx::scope(id, |cx| …)` pushes a parent).
   - **Hints:** the focused leaf's `hints()`, then each ancestor's, de-duplicated by key.
   - **Context menus:** right-click or the Menu key goes to the deepest `ContextSource` on the hit or focus chain. It returns a `ContextRequest`, and the runtime opens a `ContextMenu` overlay.
   - **Scroll:** the wheel goes to the nearest `Scrollable` on the hit chain that can still move (scroll chaining). Otherwise it is `Consumed` at the root.

6. **What an app author writes:**

   ```rust
   struct App { files: ListBox<File>, grid: DataGrid, ui: Ui }
   impl Application for App {
       fn view(&mut self, cx: &mut RenderCx) {
           let [l, r] = cx.split_h([Fill(1), Fill(3)]);
           self.files.render(l, cx); self.grid.render(r, cx);
       }
       fn update(&mut self, ev: &UiEvent, cx: &mut EventCx) {
           cx.route(ev, &mut [&mut self.files, &mut self.grid]); // focus/hit/scroll/context/hints all generic
           for e in cx.drain::<ListEvent>(self.files.id()) { if let ListEvent::Activated(i) = e { self.grid.load(i) } }
       }
   }
   ```

   No `owns`, `locate`, `on_scrollbar`, `on_wheel` or per-widget key dispatch. The app only consumes typed domain events.

**Migration order.** Each step keeps the old `on_*` methods as thin adapters until callers move, and is guarded by the existing visual snapshots.
1. `Response<E>`, `UiEvent` and `PointerEvent`.
2. `Part`-tagged hits (drop `owns` and `locate`).
3. `ScrollPane` and `Scrollable` (fixes the h-step divergence and the dead bars).
4. `Cursor`, `RowSource`, type-ahead and the chord guard.
5. `RowSelection` everywhere, plus `ClickPolicy`.
6. `RowPainter` plus reveal.
7. `OptionList` plus the `Overlay` trait.
8. `EditField` plus `Validator`.
9. `HasHints`, `ContextSource` coverage, `ContentState`.
10. `Component`, `Container`, the dispatcher and naming cleanup, then delete the glue in `src/bin`.
