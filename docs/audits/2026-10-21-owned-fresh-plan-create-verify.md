# Owned fresh-plan create and verify lifecycle

This increment adds opt-in `--owned-lifecycle` and `--owned-budget` handling to `fresh-plan` and `verify-fresh-plan`. Each owned command creates one `PrepareExecution` scope and shares it across path resolution, frozen-source checks, reviewed cohort checks, live-source verification, tool observation, Nextest inventory, plan hashing, immutable plan publication, and flushed success output. Existing calls without the new flags retain their legacy behavior.

Owned plans record the configured work budget as `timeout_seconds_per_advance`. The owned default is 200 seconds, with the existing 15-second cleanup reserve, so it no longer seals the former 225-second advance allowance. Legacy plans keep the 225-second value. Owned verification requires the supplied work budget to match the sealed advance budget. `--owned-budget` without `--owned-lifecycle` fails, including when explicitly set to the normal 200-second default.

The plan reader, inventory transforms, source and tool hashes, and plan writer now accept the shared work check. Publication checks both sides of the immutable hard link and directory sync. A failure after publication leaves the immutable plan in place and returns an error without printing success. Final success output is flushed before the last cancellation/deadline check.

Verification on the synthetic runner fixtures: 12 focused fresh-plan tests passed, including real `PrepareExecution` child termination, hash-loop deadline, chunked-write deadline, immutable post-publication deadline, output cancellation, budget matching, and CLI propagation. The complete `python3 -m unittest tools.test_frozen_baseline` suite passed 117 tests. `py_compile` passed. No live cohort plan, run key, capture, replay, ordinary check, or candidate comparison was created or run.

This increment does not complete the fresh-run initialization/verification, owned advance, ordinal guard, ordinary phase, or complete receipt lifecycle. Do not create a live plan yet. The final runner must still receive independent review after all lifecycle source and tests are integrated; stage 3 must then verify the exact final runner before any stage 4 plan can seal its hash.

## Independent P1 follow-up

The independent review at commit `17abfae6e3cafddeaea71ba7a6aea5df1499fdfa` found two bounded-work gaps: `prepare-live --owned-lifecycle` resolved paths before creating `PrepareExecution` and printed success after leaving its scope; and fresh-plan publication could leave an immutable plan without a returned creation digest. This follow-up closes those boundaries without changing legacy command defaults.

Owned `prepare-live` now places path resolution, option checks, source verification, live-source preparation, JSON serialization, flushed output, and the post-output cancellation/deadline check inside one `PrepareExecution`. It checks the work budget before and after path resolution and source verification. The no-flag legacy path retains its prior output behavior. Synthetic CLI regressions cover deadline and SIGTERM during path resolution and after final output flush.

Owned `fresh-plan` now requires an explicit `--creation-commitment-path` outside the plan root. It serializes the exact planned bytes, durably and exclusively publishes a canonical, immutable commitment containing the plan identity and whole-file digest, then flushes one JSONL record with `status=pending-plan-publication` and the commitment SHA-256 before linking the plan. The caller must retain that digest outside the plan root. The command does not claim that the commitment, plan, and stdout are jointly atomic. If a caller did not retain the prepublication digest, recovery fails closed.

`recover-fresh-plan` requires the caller-pinned `--expected-commitment-sha256`, checks that the commitment is an unchanged regular file outside the plan root, validates its exact schema and identity against the full immutable plan bytes and plan self-digest, and returns only `creation-anchor-recovered` with `verified=false`. The normal `verify-fresh-plan --expected-plan-sha256` path remains mandatory and revalidates the fixed source, cohort, live source, tool observation, and complete inventory. A pending receipt without a plan, a missing or replaced commitment, an unsafe file, a digest mismatch, or a plan collision does not recover a digest or authorize later phases. Existing artifacts are preserved for diagnosis.

The recovery receipt is not approval, source verification, key material, run initialization, capture, replay, ordinary-test evidence, candidate comparison, or product acceptance. An external supervisor must persist the pending receipt in its own trusted record before plan publication; this repository change provides the CLI boundary and recovery checks but does not implement or claim that external persistence service.

Follow-up validation after these P1 corrections: `python3 -m unittest tools.test_frozen_baseline` passed 125 tests with 0 skips in 22.669 seconds; `python3 -m py_compile tools/frozen_baseline.py tools/test_frozen_baseline.py` and `git diff --check` passed. Tests use synthetic fixture data and bounded `PrepareExecution` deadlines/signals; no real plan, key, capture, replay, ordinary check, or candidate run was created or executed.
