# Product contract

The design reference is the exact authority for appearance and interaction. Approved captures establish visual evidence for the states they cover; they do not establish untested states or parity in other workspaces. The immutable `visual-baseline` tag is historical comparison evidence, not permission to preserve known defects or a substitute for the current design reference.

## Visual system

The recorded palette uses black canvas `#000000`, chrome `#111111`, card `#18181b`, field `#1e1e22`, highlight `#2f5aa8`, and green accent/focus `#48e054`. Semantic theme tokens map these roles to component and state treatments. Behavior is explicitly defined at TrueColor, 256-color, 16-color, and monochrome (`NO_COLOR`) levels; do not approximate all levels by nearest RGB color. Hover and pressed states use deliberate ladders; contrast and focus must remain visible.

The application shell includes grouped navigation, page content, shared chrome, help, menu, hints, and feedback. Showcase groups cover shell, inputs and forms, tables, navigation, overlays, feedback, layout, text and code, and screens. Pages must demonstrate real component behavior and configuration rather than substitute drawings or one-off interaction logic.

Focus and selection treatment is layered. Only the focused owner displays a focus indicator; popup cursor modes that use a fill suppress a second row marker while the owning search/editor/select control retains its focus indicator. By default, chosen values keep the accent even when unfocused. A widget or theme may override that inactive-selection policy; a neutral backdrop/overlay policy renders the covered selection neutrally without moving the accent to another layer or erasing the selected/focused distinction. Resting seams use thin gray `│`/`─` cells; hover brightens those cells, and drag uses the accent without painting a neighboring row. Scrollbar thumbs use one glyph per track cell: gray at rest, lighter on hover, accent when pressed, and consistent across color levels. `NO_COLOR` retains state distinctions using the monochrome policy. Disabled controls ignore hover. Normal text targets 4.5:1 contrast; non-text focus/selection marks target 3:1. Verify semantic roles, covered background planes, and supported color modes rather than claiming every palette pair meets one ratio.

## Interaction

Use consistent focus, keyboard, pointer, dismissal, selection, and modal behavior across shared components. A modal focus barrier limits the focus ring and Tab/BackTab traversal to reachable modal controls, wrapping within that set. Route modal input before background content. Outside-click dismissal belongs to the owning popup and must resolve to the configured cancel behavior. Hints must advertise only keys a terminal can deliver. Preserve application-specific key overrides; do not assume one quit key or modifier policy applies everywhere.

Cursor movement and selection are distinct: moving a cursor does not automatically replace the selected set. Shift extension takes precedence over platform selection-toggle modifiers. Select All includes only selectable rows. Right-clicking an already selected row preserves multi-selection; right-clicking an unselected row selects it. Context, anchor, and fallback after item removal must be deterministic.

Quit and leave behavior respects page ownership and edits. A page gets first chance at Ctrl+C; an existing selection is copied before quit handling. If neither the page nor a selection consumes the key, configured quit behavior applies. Character shortcuts are unavailable while text has focus or is dirty. Esc is not a universal quit shortcut. Clean leaves may proceed; dirty leaves offer Save, Discard, or Cancel; a running task offers Stop or Stay. These policies remain configurable where consumers need different conventions.

Policies are layered: application/profile defaults, per-component configuration, then user key remapping. Every behavior a consumer can reasonably vary remains overridable. Standard behavior is the default when a request conflicts with an accessibility or platform convention; a requested alternative can remain an explicit option. Floating content uses the shared overlay path, including backdrop hit regions and modal dimming, rather than draw-order tricks inside a page.

Full, reduced, and paused motion modes must behave deterministically. Theme tokens define semantic roles and state ladders; level-specific palettes must preserve those roles rather than simply mapping each color to a nearest RGB value. Resizing, stale events, empty results, disabled/read-only state, long text, and narrow terminals are part of the experience and require explicit evidence. These statements define the target; a design capture or branch-specific implementation does not imply every behavior is complete.
