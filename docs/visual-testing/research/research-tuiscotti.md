## 1. What it is, architecture, maturity
- It is a Rust TUI visual-regression toolkit with two capture paths that feed one canonical `Frame` (schema v3): a pure Ratatui view, or a real executable running in a PTY (README.md top).
- **Workspace** (docs/ARCHITECTURE.md):

  | `tuiscotti-insta` | `assert_snapshot!` / `assert_screenshot!` |

## 2. Workflows (README.md)
- **Workflow 1, "pure view + `assert_screenshot!`"**: renders the production Ratatui view from fixture data with no PTY (`render_screen`) and gates canonical text plus a generation-tagged PNG through Insta.
- **Workflow 2, "live spawn + locators + snapshot (feature `pty`, on by default)"**, README.md:86:
  - Shape: `Tui::new([...]).size(40, 8).spawn()`, then `wait_predicate(...)`, `get_by_text("menu: beta").expect_visible()`, `s.snapshot()`, `s.close()`.
  - The README says "Timeouts fail WITH the last screen, never a bare deadline error. Mouse input without app-enabled reporting fails closed (`ModeNotEnabled`)."
  - Workflow 2 by itself only produces an in-memory `Screen`. **It does not write ansi/png/html/txt.** To get files and baselines you have to add `render::frame_from_screen(&screen, profile)` (crates/tuiscotti-render/src/render/frame.rs:19) and then `GroupedStore::check_with(...)`.
  - The real-binary reference is `crates/tuiscotti-fixtures/tests/journey.rs` (`Tui::new([env!("CARGO_BIN_EXE_menu_fixture")])`, `press("Down")`, `wait_stable`, `Locator::expect_count`).
- **Workflow 3, "CLI capture + frozen review"**: `tuiscotti capture` only records stdout/stderr and a manifest, not screen frames. `render` turns `frame.json` into formats, `diff` compares PNGs, and `import` reads frozen trees. **The current CLI cannot script keys, mouse or resize into a PTY capture.** That was the removed `run --send`.

## 3. Formats, rendering, diff, scripting, determinism
- **Grouped store**, the right fit for us (docs/SNAPSHOTS.md §Grouped, crates/tuiscotti-runtime/src/grouped/mod.rs):
  - Exactly four approved files per scenario: `.ansi` (normalized SGR dump, the cell-exact gate), `.txt`, `.png` (decoded-pixel gate) and `.html` (byte gate at render level).
  - Actuals, diffs and the report go to `<root>.actual/` and `<root>.diff/` by default (`with_actual_root` / `with_diff_root` / `with_report_path`).
  - If any of the four approved files is missing, the check fails closed as MissingApproval (grouped/check.rs).
- **Other formats:**
  - `render --format` accepts `txt, ansi, json, svg, html, png` (docs/CLI.md).
  - "ASCII" is a separate 7-bit projection that records its substitutions, available in the Rust API only (`formats::capture_all`; crates/tuiscotti-render/src/formats/ascii.rs). It is **not** a grouped artifact, so the PO's "ascii" most likely means `.ansi`.
  - Also available: asciicast v2, GIF, APNG, plus sixel/kitty/mp4 modules under `export/`.
- **PNG rendering:**
  - Pure-Rust `swash` rasterizer with vendored fonts: JetBrainsMono Nerd Font Mono R/B/I/BI, plus Noto Symbols/Symbols2/CJK-jp subsets (crates/tuiscotti-render/fonts/).
  - Profile: 10×21 cells at 16px, scale ×2, font SHA-256 checked when loaded (docs/ARCHITECTURE.md §Key types; DECISIONS.md §5).
  - DECISIONS.md §5 claims "byte-identical PNGs on any machine", with no system fonts.
  - Glyphs no face covers (colour emoji, Hangul) render as deterministic tofu and are listed in `<name>.png.fidelity.json`.
  - Cross-arch evidence: the committed approvals in `crates/tuiscotti-fixtures/tests/visual/approved/` are gated at threshold `1.0` (tests/visual.rs:46) in ubuntu-x64 CI while the author develops on macOS. I infer from that, but did not verify, that PNGs are byte-identical across aarch64 and x86_64.
- **HTML:**
  - The grouped `.html` comes from `Renderer::render_html`: the PNG as base64 plus the frame JSON with `created_unix = 0` (render/renderer.rs:271–276).
  - In our repo each one is **about 1.6 MB**. That is why `snapshots/` is 12 GB.
  - `formats::html_static` is a script-free variant.
- **Diff and review:**
  - The PNG gate is an exact decoded-pixel compare; re-encoding a PNG still passes.
  - `pixel_threshold` together with `PerceptualPolicy` gives a tolerance (`score >= threshold`); NaN or out-of-range values are rejected.
  - On mismatch a red-overlay diff PNG is written.
  - `report.html` links the files rather than embedding them.
  - Eight statuses: `matched, cells-differ, pixels-differ, dimension-mismatch, missing-approval, corrupt-approval, capture-incomplete, not-checked` (docs/SNAPSHOTS.md).
- **Updating baselines:** approval is explicit only. There is deliberately no `BLESS=1`, and a test proves no env var accepts (docs/DECISIONS.md §1). The grouped API is `GroupedStore::accept(name)` / `accept_all()`, Rust only (grouped/mutate.rs:18,45). The CLI `accept` targets the classic store, so we would need a tiny ignored "accept" test or an xtask.
- **Scripting:**
  - Keys use `+` chords (`ctrl+Up`); kitty keyboard is on by default.
  - Mouse is SGR/UTF-8/legacy and requires the app to enable mouse reporting.
  - `resize(cols, rows)` reflows through the emulator, but scrollback is not reflowed (LIMITATIONS.md).
  - Signals are unix-only.
  - **There is no clock or time control.** Waits use real deadlines; `wait_stable` uses a 200 ms quiet period (`DEFAULT_STABLE_QUIET`, tui/limits.rs:32).
- **Environment control:**
  - The child inherits the parent environment unless `env_clear(true)`.
  - The only default added is `TERM=xterm-256color` (tui/builder.rs:292–315, tui/profile.rs).
  - `COLORTERM`, `NO_COLOR`, `TZ` and `LANG` are not managed, so we must set them explicitly per capture.
  - Synchronized output (DEC 2026) is rejected as unsupported.
  - Unknown escape sequences are silently ignored.
  - OSC 4/10/11 overrides are dropped (LIMITATIONS.md).
- **Parallelism and speed:**
  - Stores use per-name files and atomic renames, so parallel nextest is safe (docs/TESTING.md §CI wiring).
  - Measured local numbers, Apple silicon (docs/PERFORMANCE.md lines 176–183):
    - full render plus compare: about 15 ms at 120×40
    - PTY readiness to verdict: p50 15.5 ms
    - 683-test suite: about 33 s
  - The commit "tier grouped checks, pace PTY input, fast PNG compare" (`0a2e490`) landed *after* our pin.

## 4. Integrating with a Cargo project
- **As a dev-dependency:**
  ```toml
  tuiscotti = { git = "https://github.com/tailrocks/tuiscotti", rev = "a47c9aa..." }
  ```
  `pty` is a default feature.
  - Integration tests in `tests/` get `CARGO_BIN_EXE_showcase` and the others at compile time.
  - Spawn with `Tui::new([env!("CARGO_BIN_EXE_showcase")]).args(...)`. That is the same binary `cargo run --bin showcase -- args` builds, with no nested cargo. This is the pattern in crates/tuiscotti-fixtures/tests/common/live.rs:10–19.
  - `Tui::cargo_bin(name)` also resolves `CARGO_BIN_EXE_*` at runtime and searches target dirs as a fallback (command/types.rs:236–342).
  - The MSRV and toolchain rise to Rust 1.98, and the pins are exact `=` versions (`ratatui =0.29.0`, `crossterm =0.28.1`), so check for conflicts with our lockfile.
- **As a CLI:** the current CLI cannot drive a PTY scenario, so it is not usable for this. Use the library.
- **GitHub Actions** (docs/TESTING.md §CI wiring): run `cargo nextest run --locked …`, then `actions/upload-artifact@v4` with `if: always()` on the actual dir, diff dir and `report.html`. Never run `accept` in CI. Do not cache actuals or diffs.

## 5. Gaps, risks and recommendations
**Risks:**
1. **Upgrade cost.** `tuisnap::pty::{run_once, Session, PtyOptions}`, `tuisnap::{Profile, VENDORED_FACES}` and the CLI `run`/`accept --grouped --all` were removed. Every file under `tests/visual_baseline/` needs porting to `tuiscotti::tui::{Tui, Session}`.
   - The engine changed (vt100 to termpane/alacritty), the profile name strings changed (`tuisnap-default` to `tuiscotti-default`), and the HTML embeds a renderer identity.
   - Expect **every approved `.html`, and possibly `.png` and `.ansi`, to change**. That means a full re-bless of 7,550 scenarios.
2. **Repo bloat.** The `.html` files are about 1.6 MB each, redundant with the `.png` plus `.ansi`, and make up most of the 12 GB. GroupedStore *requires* all four, so dropping HTML would need an upstream option or a fork.
3. **Single maintainer, no releases**, self-described research grade, docs that contradict each other on the PTY engine, and no macOS CI. Pin by rev and vendor-review each bump.
4. **PNG determinism.** Pure Rust with vendored fonts and linux-x64 CI evidence is good. macOS-vs-Linux equality is not proven by any CI lane. Mitigate by generating and approving baselines on the same OS and arch as CI (ubuntu-24.04) or in a container.
5. **Flakiness.** With no clock control, spinners, cursor blink, timestamps and animations can cause flakes. Readiness must be content-gated: journey.rs notes that `wait_stable` can return a blank revision 0 on a slow first draw. The emulator also drops some OSC sequences.

**Recommendations:**
- **Workflow:** Workflow 2 as a library: `Tui::new([env!("CARGO_BIN_EXE_<bin>")])` with an explicit environment (`env_clear(true)` plus `TERM`, `COLORTERM`/`NO_COLOR` per colour level, `LANG=C.UTF-8`, `TZ=UTC`, a fixed `HOME`/cwd). Then the scripted keys/mouse/resize, a content wait (`Locator::expect_visible`) followed by `wait_stable_quiet`, then `snapshot()`, then `frame_from_screen(&screen, "tuiscotti-default")`, then `GroupedStore::check_with(&mut shared_renderer, name, &frame, 1.0)`, then `ensure_matched()`. Calling `check_with` with one shared `Renderer` reuses the parsed faces and glyph cache.
- **Layout:** keep the current `snapshots/<app>/<group>/<cols>x<rows>/<palette>.{ansi,txt,png,html}`. Actuals and diffs go to `target/tuiscotti/{actual,diff}` and the report to `target/tuiscotti/report.html` via `with_actual_root` / `with_diff_root` / `with_report_path`. Upload those three paths in CI.
- **Approval:** an `#[ignore]` test (or xtask) that calls `GroupedStore::accept_all()`, run only locally after reviewing the report.
- **Speed:**
  - Use one `#[test]` per scenario so nextest parallelizes them.
  - Build the binaries once (`cargo nextest run --cargo-profile` with opt-level 1 or release).
  - Shard across CI jobs with `--partition hash:k/N`.
  - Keep a small always-on smoke subset and run the full matrix nightly or on label.
  - Shrink the matrix: the five colour levels × sizes product (`holla/audit/rust/<size>/{16,256,nocolor,none,truecolor}`) is the main multiplier.
- **Before committing to the upgrade:** prototype one app's group on tuiscotti `a47c9aa` in a branch and measure how much the artifacts churn and how long a run takes in CI before re-blessing everything. The alternative is to stay on the pinned tuisnap rev, which already provides Workflow 2 plus the four formats in our tree.
